# Formato: <fichero-que-la-contiene>:<linea> <ref-rot a>  #  <por que>
#
# POR QUE ESTE FICHERO EXISTE
#
# El auditor reportinga 6 ROTA dentro de 06-INGENIERIA-INVERSA/findings, y al
# mirarlas solo UNA parecia un error. Las otras cinco eran:
#
#  - 4 en 051, que CITA nombres inexistentes como ejemplo (`CLAUDE.md`,
#    `docs/config.md`, `docs/rules.md`, `DESIGN.md`). Citar un nombre roto
#    convierte la cita en referencia rota: el auditor no puede distinguir
#    "menciono esto" de "mire esto". No se corrigen; corregirlas seria
#    destruir el ejemplo.
#
#  - 1 en 021:154, que es la UNICA que de verdad parece un error y NO lo es:
#    `022-pte-productor-sdma-gfx8.md` no existe porque esa sesion lo renombro
#    a `023-pte-productor-sdma-gfx8.md` al resolver una colision de indice, y
#    021 CUENTA esa colision. La frase es un registro historico de un nombre
#    que existio. Corregirla a `023-` haria que 021 contara una colision con
#    dos ficheros 022 cuando uno jamas existio con ese nombre: se arreglaria la
#    referencia rompIendola.
#
# CLASE QUE ESTO PRODUCE
#
# El auditor pasa a distinguir tres clases, no dos:
#
#   ROTA               el fichero no existe y no hay razon
#   ROTA_HISTORICA     no existe, y hay una razon escrita aqui
#   RUTA_EQUIVOCADA    existe, pero no donde dice el texto
#
# Y la distinction no es cosmetica: una ROTA se corrige escribiendo, una
# ROTA_HISTORICA se corrige documentando por que no, y una RUTA_EQUIVOCADA
# normalmente es la convencion de citar findings por nombre desnudo.
#
