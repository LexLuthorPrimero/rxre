## Resumen
`amdgpu_fence_info` (read-only, rc=0, 2267 B) muestra que **todos los rings están idle** bajo idle:\n\n- **ring 0 (gfx)**: Last signaled fence = `0x00a9d005` == Last emitted `0x00a9d005` (commit)\nfence). `Last signaled trailing fence=0`, `preempted=0`, `reset=0`, `both=0`.\n\n- **ring 1 (comp_1.0.0)**: signaled=1==emitted=1 (idle).\n- **ring 2 (comp_1.1.0)**: signaled=1==emitted=1 (idle). (Hay 4 rings compute: comp_1.{0-3}.0. + sdma0/1.)\n\n→ signaled == emitted en todos los rings ⇒ **no hay trabajo pendiente** (el CP ha committeado todo).\nEsto CONFIRMA §1607 (engines idle, busy=0), §1611 (firefox/RDD fences signalled) y §1609 (idle).\n\n**Gap (§58 [09])**: los archivos de ring-buffer `amdgpu_ring_gfx`, `amdgpu_ring_sdma0`,\n`amdgpu_ring_kiq_0.2.1.0` devuelven **EINVAL (Errno 22)** al read() — no son `cat`-ables\ndirectamente (debugfs de ring-buffer con read especial/sequence). No se pudo leer el PM4\ncommand stream (§17 PM4→IB) read-only. §42/§43: no forzar writes a estos (semántica unknown).\n\n## Evidencia técnica\n### amdgpu_fence_info (debugfs, read-only)\n```\n--- ring 0 (gfx) ---\nLast signaled fence          0x00a9d005\nLast emitted                 0x00a9d005   # == signaled -> todo commit/idle\nLast signaled trailing fence 0x00000000\nLast emitted                 0x00000000\nLast preempted               0x00000000\nLast reset                   0x00000000\nLast both                    0x00000000\n--- ring 1 (comp_1.0.0) ---\nLast signaled fence          0x00000001\nLast emitted                 0x00000001   # == signaled -> idle\n--- ring 2 (comp_1.1.0) ---\n... (mismo patrón; 4 compute rings + sdma0/1)\n```\n- `signaled == emitted` ⇒ CP ha avanzado hasta el último emit (idle); `trailing=preempted=reset=0`\n  ⇒ sin preemción/reset pendiente. §17 Sync→Fences (idle).\n- Los rings GFX idle + firefox/RDD (§1611) con fences signalled ⇒ firefox/RDD están IDLE (offload reservado).\n\n### Ring-buffer read gap (debugfs EINVAL)\n- `open('/sys/kernel/debug/dri/1/amdgpu_ring_gfx','rb').read()` → `Errno 22 Invalid argument`.\n- `amdgpu_ring_sdma0`, `amdgpu_ring_kiq_0.2.1.0` → mismo EINVAL.\n- Interpretación (§9): estos son debugfs "sequence files" que requieren un read protocol específico\n  (o son triggers de dump), no un file text. `cat`/`open` directo falla. No es error del GPU;\nes un limitante de la interfaz debugfs de este kernel/amdgpu.\n- Alternativa read-only (§46/§108): `umr -g =0000:01:00.0 -r gfx800.mmCP_CSQ_*...` o dump filtrado;\n  o `amdgpu_gpu_recover`/`amdgpu_vm_*` (text). §1613: probar umr -O bits sobre CP/SDMA regs.\n\n## Decisiones\n- D26 (RXRE-008): bajo idle, los rings (gfx + comp) están IDLE (fence_state) ⇒ el CP/SDMA no\n  procesa PM4/IB. El SCLK floor (§1608) bajo idle NO es trabajo de rings (idle) ⇒ sigue siendo DPM\n  policy (§1609 D17), no load de rings.\n- D27 (RXRE-008): para reconstruir el PM4 command stream (§17 PM4→IB) necesario el ring buffer\n  content; debugfs `amdgpu_ring_*` no lo expone (EINVAL). Usar umr -O bits sobre regs CP/SDMA (§1613)\n  o el VM `gpuvm` dump (riesgo/permiso). No forzar writes a ring debugfs (semántica unknown §43).\n- D28 (RXRE-008): `fence_info` (signaled==emitted) es un oracle read-only barato y fuerte de \"CP idle\".\n\n## Verificación
- amdgpu_fence_info rc=0, readable, signaled==emitted en gfx+comp rings. ✓\n- idle (trailing/preempted/reset=0). ✓\n- Coherente con §1607 (GRBM busy=0), §1611 (firefox/RDD fences signalled). ✓\n- read-only (debugfs open rb, NO write, NO display, iGPU intacta). ✓\n\n## Limitaciones\n- Sólo fence STATE (no el ring buffer content / PM4 stream) ⇒ no se reconstruyó el IB/PM4.\n- amdgpu_ring_* (buffer content) no readable (EINVAL) → GAP de observabilidad §17 PM4/IB. §58 [06].\n- Snapshot de fence; no time-series de fence counters.\n\n## Próximos pasos (§58 GLOBAL WORK SCAN)\n- 1613 (frontera, read-only umr): leer CP/SDMA status registers (mmCP_STALLED_STAT1/2/3 0x219d/219e/219c,\n  mmSDMA0_STATUS) via `umr -O bits` bajo idle → confirmar SDMA/CP idle a nivel registro (§17).\n- 1614 (frontera): `amdgpu_vm_info` completo (binary-safe) → VMID por pid §17 VMID.\n- 1615 (frontera, gating §42 reversible): SCLK bajo firefox offload-activo vs idle (correlacionar §72).\n\n<signed> Sistema Autónomo RXRE — RXRE-008 (single active agent; iGPU 0000:00:02.0 untouched; GPU 0000:01:00.0 read-only debugfs + umr)\n
