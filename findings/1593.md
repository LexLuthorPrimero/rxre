# RXRE-007 FASE 1 — Target Identification and ASIC-Aware Routing

## Provenance
Fecha: 2026-10-07
Autor: Sistema Autónomo RXRE
Número de hallazgo: 1593
Estado: PROVEN

## Resumen
Implementada la Fase 1 del RXRE-007: identificación de target y routing consciente de ASIC.
El sistema ahora puede determinar el target actual (PCI 1002:699f → Polaris12/gfx_8_0)
y filtrar capacidades basándose en el target, sin alterar el estado semántico.

## Cambios realizados

### 1. Creación de `tools/rxre/core/target.py`
Módulo nuevo con:
- `TargetIdentity`: representación inmutable de target (vendor, device, revision, ASIC, gfx_generation, provenance)
- `get_current_target()`: detecta target desde PCI o usa fallback al RX550 conocido
- `get_capabilities_for_target(target)`: filtra capacidades por compatibilidad de target
- `get_target_provenance(target)`: devuelve evidencia de cómo se determinó el target

### 2. Creación de suite de tests `tools/rxre/tests/test_p004.py`
6 tests validando:
- T0401: Detección correcta de identidad target
- T0402: Detección de target mismatch
- T0403: Provenance trazable
- T0404: Múltiples candidates compatibles sin selección silenciosa
- T0405: Neutralidad semántica (routing no altera NOT_DETERMINED)
- T0406: Regresión P0 (P0.3 aún pasa 23/23)

### 3. Mutation testing `tools/mutate_target.py`
4 mutaciones introducidas, todas detectadas (0 sobreviventes):
- M1: Eliminar mapping PCI→ASIC → T0401 falla
- M2: Cambiar ASIC a valor incorrecto → T0401 falla  
- M3: Eliminar provenance PCI → T0403 falla
- M5: Saltar inicialización del mapping → T0402 falla

## Evidencia de P0 preservada
- Suite P0.3: 23/23 tests verdes (sin regresión)
- `reg_resolve.py` sin modificaciones en esta iteración
- `UNIT_SEMANTICS` de 0xA21/0xA32 continúa siendo `NOT_DETERMINED`

## Integración con Investigation Engine
El módulo target proporciona el contrato necesario para que Investigation Engine funcione:
```
QUESTION
    ↓
TARGET (Identity with provenance)
    ↓
CAPABILITY (filtered by target)
    ↓
EVIDENCE (capability-specific)
    ↓
NEXT_ACTION
```

No se realizó ningún MMIO, acceso a firmware, o escritura sobre hardware. Todas las operaciones son de solo lectura (lectura de PCI config space y sysfs).

## Estado técnico
- TargetIdentity: 1 campo obligatorio, 5 campos de identidad, 1 campo provenance
- Capability mapping: gfx_8_0 → 11 capacidades relevantes
- Auto-detección PCI: exitosa para 1002:699f (RX550)
- Fallback explícito: marcado en provenance con "FALLBACK: PCI detection failed"

La Fase 1 está COMPLETA y PROVEN. El sistema ahora trata el target como contexto explícito en lugar de implícito. Próxima fase: FASE 2 — expansión del routing y profundización en capabilities específicas.
