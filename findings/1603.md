# RXRE-008 FINDING 1603 — OBSERVED vs MODELED Distinction

## Provenance
Fecha: 2026-10-07
Autor: Sistema Autónomo RXRE
Número de hallazgo: 1603
Estado: PROVEN

## Resumen
Verificado que RXRE distingue inequívocamente entre valores OBSERVADOS (medicionesdirectas) y valores MODELADOS (interpretaciones/derivaciones). Esta separación epistemológica es central en el diseño del Relation Engine y el módulo de investigación.

## Contexto
El Principio Fundamental de RXRE establece:

```
RXRE result
    ↓
evidence
    ↓
independently justified interpretation
```

Nunca:

```
RXRE result
    ↓
truth
```

Como preocupación central, se incorporó la disyuntiva OBSERVED vs MODELED para evitar que una representación calculada o inferida parezca una lectura directa.

## Evidencia técnica

### 1. Resultados OBSERVADOS
- Campo `status='observed'` en tabla `results`
- Campo `raw` conserva el valor sin interpretar
- Representa medición o lectura directa de hardware/software
- Ejemplo: `resultado(tipo='register', valor='0xA21', status='observed', raw='0xA21')`

### 2. Cadenas MODELADAS
- Campo `epistemic_state='NOT_DETERMINED'` en tabla `relation_chains`
- Campo `limitations` documenta la naturaleza del modelo
- Representa interpretación o deriva sin certeza garantizada
- Ejemplo: `registrar_cadena(epistemic_state='NOT_DETERMINED', limitations='derived from pattern match - MODELED interpretation')`

### 3. Distinción comprobada
| Característica | OBSERVADO | MODELADO |
|---|---|---|
| `results.status` | `observed` | N/A (en chains) |
| `relation_chains.epistemic_state` | N/A | `NOT_DETERMINED`, `PROVEN` |
| `results.raw` | Valor sin modificar | N/A (preservado por transparencia) |
| `relation_chains.limitations` | N/A | Documenta incertidumbre |
| Provenance | `res_*` → results/edges | `res_*` → results/relations |

### 4. Query de verificación
RXRE permite distinguir mediante consultas:

```sql
-- Valores observados (mediciones directas)
SELECT result_id, value, status, raw FROM results WHERE status='observed';

-- Cadenas modeladas (interpretaciones)
SELECT relation_id, epistemic_state, limitations FROM relation_chains WHERE epistemic_state='NOT_DETERMINED';

-- Cadenas con certeza
SELECT relation_id, epistemic_state FROM relation_chains WHERE epistemic_state='PROVEN';
```

## Decisiones de diseño

### Separación explícita
RXRE no confunde:
- `resultado` con `status=observed` → medición directa, sin interpretación automática
- `cadena` con `epistemic_state=NOT_DETERMINED` → interpretación/modelo sin certeza garantizada
- `cadena` con `epistemic_state=PROVEN` → interpretación con evidencia suficiente

### Transparencia del raw
El campo `raw` en resultados se conserva SIEMPRE (norma de normalize.py):
- Permite detectar si un normalizador se equivocó
- Permite la recuperación del dato original
- Evita que la interpretación se pase por hecho

### Cadenas con estados epistemológicos claros
Cada cadena debe tener un `epistemic_state` explícito:
- `PROVEN`: cadena completa respaldada por evidencia
- `PARTIAL`: cadena a medias, algunos segmentos con evidencia
- `NOT_DETERMINED`: sin evidencia suficiente (modelo sin certeza)
- `REFUTED`: evidencia contradice la cadena
- `BLOCKED`: dependencia sin resolver

## Verificación realizada
Test manual que confirma:
1. ✓ RXRE distingue resultados observados de cadenas modeladas
2. ✓ Los estados epistemológicos no se confunden automáticamente
3. ✓ El campo `limitations` documenta la naturaleza de cada interpretación
4. ✓ Las consultas SQL pueden filtrar por estado observado vs modelado
5. ✓ Mutation testing confirma que la separación es intencional y no accidental

## Convergencia con el Principio Fundamental
```
RXRE result
    ↓
evidence (raw preservado)
    ↓
interpretation con estado explícito
    ↓
claim con discriminante
    ↓
validación independiente
```

No:
```
RXRE result
    ↓
interpretación oculta
    ↓
truth asumida
```
