## 2. Causa raíz (demostrada)

`tools/rxre/core/store.py`, `checkpoint()`:

```python
inv   = investigacion(c, session=session, target=target, limite=500)
filas = inv["entradas"]
...
"limitations": inv["limitations"] or [ <frase de sesión vacía> ],
```

`investigacion()` documenta y cumple: **devuelve `limitations` NO VACÍO si y solo si el filtro
(`session`/`target`) no trajo filas** (líneas 768-779):

```python
lims = []
if not filas:
    if total == 0:  lims.append("la tabla research esta VACIA…")
    else:           lims.append("hay N entradas… NINGUNA cumple el filtro…")
```

Por tanto, con la sesión **poblada** `inv["limitations"]` es `[]`, y el `or [...]` del
`checkpoint` emitía la frase de sesión vacía **precisamente cuando había filas**. La polaridad
de la condición estaba **invertida**: la frase de vacío estaba indexada al caso poblado y no al
vacío.

**Relación filtro ↔ datos (la que pide el encargo).** `hipotesis_abiertas`, `hipotesis_refutadas`,
`claims`, `fronteras`, `notas` y `siguiente_accion` se derivan de **las mismas filas `filas`** que
`investigacion()` devolvió (`por_status`/`nxt` sobre `filas`). `limitations` es la única clave que
**no** se derivaba de `filas` para decidir su condición: se derivaba de `inv["limitations"]`
—que sí lo hace— pero el `or` reintroducía la decisión invertida.

Clasificación: **PROVEN** (una sola causa, línea de código citada, contraste medido en cuatro
casos y en el test de regresión). No es `NOT_DETERMINED`.

La segunda inconsistencia latente del mismo texto (decía «la evidencia existe» e imprimía
`Hay 0 operations y 0 results`) queda resuelta al exigir evidencia real en la condición.

## 3. Corrección (mínima, causa raíz)

```python
lims = list(inv["limitations"])
if not filas and (ops or res):
    lims.append("no hay ninguna entrada de research para esta sesion: … Hay %d "
                "operations y %d results …" % (ops, res))
...
"limitations": lims,
```

- Sesión poblada (`filas` no vacío) → `limitations == []`: no afirma vacío de razonamiento.
- Sesión sin filas y **con** evidencia → mensaje de vacío, ahora **cierto** (afirma que la
  evidencia existe y la imprime).
- Sesión sin filas y **sin** evidencia → no se añade: `investigacion()` ya nombra el motivo real
  («tabla VACIA» / «no coincide el filtro»), que es lo que exige `test_field005` (líneas 344-351).

No se introdujo una interpretación nueva de `research`: se usó el modelo existente
(`investigacion()`), y solo se corrigió la condición.
